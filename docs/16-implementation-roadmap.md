## Owner-directed real workflow

The first useful workflow is: obtain/import real Binance BTCUSDT perpetual historical
trade data for a user-selected interval in 2024–2026; validate and version the raw and
normalized dataset; select a real runnable strategy; configure only execution
assumptions supported by the selected data; submit an asynchronous backtest to the
vendored hftbacktest engine; persist reproducible inputs and actual outputs; and
inspect the result with clear data coverage and modeling limitations. The UI is
implemented around this workflow and connected to real services as each slice becomes
available. It is not a prerequisite to finish a mock-only desktop application.

**Data fidelity labels are mandatory.** Trades-only data records executed trades but
not resting liquidity or historical queue position. It may be used for strategies and
engine modes whose input/execution semantics are supported by the engine, but results
must disclose that it does not reproduce a historical order book or support claims of
historically observed queue position. L1 provides the best bid/ask; L2 provides price
levels with aggregate size; L3 provides individual resting orders. L2 is the next
target after the trades-only vertical slice. Candles are suitable for bar strategies
only and are not a substitute for trade or depth events in an HFT backtest.

## Revised sequencing

1. **Active now — audit and stabilize existing real backend/engine work.** Reconcile `STATE.md`,
   the coordination board, and actual build/acceptance results. Treat historical
   `DONE` claims as unverified until current checks pass; do not continue live-order
   work based on those markers.
2. **Active now — real BTC perpetual trade-data vertical slice.** Implement historical import,
   validation/provenance, dataset selection, an honest trades-only compatible engine
   path, one real strategy, asynchronous job execution, persisted results, and the
   minimum UI needed to operate and inspect it. No market data or backtest result in
   this flow may be generated by a mock runtime.
3. **Next — L2 historical depth.** Import and validate Binance perpetual depth snapshots and
   incremental updates, reconstruct a continuous book, align trades, and run the
   hftbacktest L2 path with explicit queue/latency/fee assumptions and tested
   limitations.
4. **Then — research workbench.** Build out the main and secondary monitor workflows against
   real normalized events, jobs, and persisted experiments. Replace or remove mock
   consumers as each real source is connected; do not spend a phase completing every
   panel against fabricated market state first.
5. **Then — AI research.** Integrate OpenRouter behind a provider boundary, support free
   models configured by model ID, keep credentials server-side, ground explanations
   in persisted experiment/data evidence, and require user review before generated
   strategies or proposed experiment batches execute.
6. **Later — paper mode and operations.** Build and validate isolated paper execution
   after real research/backtests work. Live order routing, credentials, and scale-out
   require a separate owner-reviewed gate and are not part of the current milestone.

Each item is a sequencing directive; task-level contracts and acceptance criteria
must be written into the relevant docs before executor implementation. The existing
Phase/Block entries below remain useful where compatible, but mock-first F.7 work is
superseded and must not be claimed as satisfying real-data acceptance.
